# Student 1 Test Designs

All tests are recommended for a new functional GTest adjacent to `src/modules/commander/failsafe/failsafe_test.cpp`, registered with `px4_add_functional_gtest` and linked to `failsafe mode_util`. Use a fresh `FailsafeTester`, zeroed `failsafe_flags_s`, armed rotary-wing state, explicit timestamp, and `COM_FAIL_ACT_T` set to the stated value unless a row says otherwise. Do not copy upstream test bodies; these are derived scenarios and IDs.

| ID | Scenario and controlled setup | Expected result | Obligations |
|---|---|---|---|
| TC-FS-01 | Call `actionStr` for every enum value None, Warn, FallbackPosCtrl, FallbackAltCtrl, FallbackStab, Hold, RTL, Land, Descend, Disarm, Terminate, Count, and `static_cast<Action>(255)`. | Exact strings for valid actions; `(invalid)` for Count/invalid. | OBL-FS-001 |
| TC-FS-02 | Call `modeFromAction` for all seven mode-producing actions and for None, Warn, Disarm, Terminate, Count with sentinel `user_intended_mode=MANUAL`. | Correct mapped mode for seven actions; sentinel preserved for other actions. | OBL-FS-002 |
| TC-FS-03 | First update at `5_s`, no flags, armed POSCTL; second update at `5_s+10_ms`, no flags. | Both return intended mode and selected action is None; initialization and normal commit paths execute. | OBL-FS-003, OBL-FS-008 |
| TC-FS-04 | Trigger an OnModeChangeOrDisarm action, then update with `armed=true -> false`; separately trigger and update `false -> true`. | Action is removed and takeover state is cleared on each transition. | OBL-FS-004 |
| TC-FS-05 | Activate a mode-change-cleared failure, then change intended mode without setting explicit update flag. | Changed mode is detected and the action clears. Repeat with explicit `user_intended_mode_updated=true` and unchanged mode. | OBL-FS-005 |
| TC-FS-06 | Enable finite deferral for 2 seconds, trigger a deferrable failure at `t`, update at exactly `t+2_s`, then at `t+2_s+1_us`; repeat with timeout `-1`. | Exact expiry does not clear; strictly past expiry clears; negative timeout never expires. | OBL-FS-006, OBL-FS-007 |
| TC-FS-07 | Use a callback counter, transition None -> Warn and then repeat same Warn without a new warning. | Callback occurs on worsening/new notification and notification-required state is reset on the next update. | OBL-FS-008, OBL-FS-012 |
| TC-FS-08 | With `COM_FAIL_ACT_T=5.0`, trigger delayed action; use `dt=1_s` (< current delay), then `dt` equal to remaining delay; clear action and allow regrowth above configured cap. | Delay subtracts while active, reaches zero at equality, regrows at one quarter rate, and never exceeds 5 seconds. | OBL-FS-009 |
| TC-FS-09 | Exercise active delay with elapsed less than current delay and greater than current delay by triggering/clearing failures at controlled times. | Remaining delay subtracts for smaller elapsed; becomes zero for larger elapsed. | OBL-FS-010 |
| TC-FS-10 | Trigger manual-control loss twice without clearing between updates; use same caller generated by `FailsafeTester`. | One action remains; second check updates the existing action and does not allocate a duplicate. | OBL-FS-011 |
| TC-FS-11 | Set `COM_FAIL_ACT_T=5.0`, trigger a non-Warn Auto action; repeat with `0.1` and `0.0`; trigger Warn. | Values above `0.1` use Always and start delay; `0.1` and below use AlwaysModeSwitchOnly; Warn does not start action delay. | OBL-FS-012 |
| TC-FS-12 | Trigger two actions with different severities and causes. | Highest enum severity is selected and its cause is retained; restrictive takeover policy wins. | OBL-FS-012, OBL-FS-019 |
| TC-FS-13 | Trigger a default WhenConditionClears action, then clear its flag with deferral disabled. | Action slot is invalidated immediately and selection returns None. | OBL-FS-013 |
| TC-FS-14 | Trigger OnModeChangeOrDisarm and Never actions; clear their flags without mode/disarm, then disable deferral for a deferrable action. | OnModeChangeOrDisarm/Never retain a non-failing slot; a deferrable retained action is removed while deferral is active. | OBL-FS-013 |
| TC-FS-15 | Trigger an action, then use a custom tester update that omits that check on the next update. | Non-activated action is removed according to its clear policy and activation marker resets. | OBL-FS-014 |
| TC-FS-16 | Document an attempted eight-plus distinct caller setup. | If reachable without changing production contracts, verify severity replacement; otherwise record defensive path as not practically reachable and do not claim coverage. | OBL-FS-015 |
| TC-FS-17 | Update armed state in TERMINATION mode; then clear flags, disarm, and change mode. | Selected action remains Terminate in every update. | OBL-FS-017 |
| TC-FS-18 | Update with `armed=false` and an active failure flag. | Selected action is None and intended mode is unchanged. | OBL-FS-018 |
| TC-FS-19 | Activate deferrable failure and enable deferral; repeat with non-deferrable motor+critical failure. | Deferrable action becomes None with `failsafeDeferred=true`; non-deferrable Terminate is selected immediately. | OBL-FS-019, OBL-FS-020 |
| TC-FS-20 | Trigger RTL/Land/Descend with positive delay, zero delay, Disarm, and Terminate. | Only eligible non-terminal/non-disarm actions enter delayed Hold. | OBL-FS-021 |
| TC-FS-21 | Exercise takeover matrix with Always and AlwaysModeSwitchOnly policy, active/inactive takeover, mode-switch request, stick request, and no request. | Results match MC/DC matrix: Warn only when the policy/request permits; stick takeover changes mode to POSCTL. | OBL-FS-022, OBL-FS-023 |
| TC-FS-22 | Supply a subclass fallback greater than Warn during takeover and one equal to Warn. | Greater fallback replaces Warn; equal fallback does not. | OBL-FS-024 |
| TC-FS-23 | Set each mode requirement mask so POSCTL, ALTCTL, STAB, LOITER, RTL, LAND, and DESCEND are individually unavailable, then trigger an action. | Selection falls through to the next feasible action; when all are unavailable it reaches Terminate. | OBL-FS-025, OBL-FS-028 |
| TC-FS-24 | Start with intended AUTO_LAND and an RTL action; repeat with mode unavailable and with a non-RTL action. | Available redundant RTL converts to Warn and clears delayed action; unavailable/nonmatching cases do not. | OBL-FS-026 |
| TC-FS-25 | Repeat redundant-action guard for AUTO_RTL and AUTO_PRECLAND, including Land and RTL alternatives. | AUTO_RTL suppresses RTL; AUTO_PRECLAND suppresses RTL/Land only when the mode can run. | OBL-FS-026 |
| TC-FS-26 | Create positive delay, then make selected action already beyond Hold, Hold unavailable, and takeover active. | Delay is cleared in each condition; otherwise it is retained. | OBL-FS-027 |
| TC-FS-27 | For each `modeCanRun` requirement, set the invalid flag true with its mode bit set, then clear the bit; set `mode_req_other` directly. | Invalid+required rejects; invalid+not-required accepts; other mask rejects. | OBL-FS-028 |

The upstream tests are baseline evidence only. Student 2 should implement independently from these exact controls and expected results, and record execution as `NOT RUN` in the design workbook until implementation occurs.
